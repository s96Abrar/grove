# Supacode feature coverage

Reference: upstream commit `1ffcc2e93c3f74fe3d52183176542fa8852ad2ba`, inspected on 2026-10-28. This is an implementation checklist, not a claim of feature parity. It covers the README workflows, global/repository settings, CLI surface, and feature reducers examined below; it is not a complete inventory of every private method or hidden behavior.

## Status and evidence

**Implemented** means present in Grove 0.3 source; this is not a blanket claim of executed UI acceptance. **Partial** means the described subset exists. **Missing** means absent from current source. Verification is bounded by [validation](VALIDATION.md). The PTY/screen backend check establishes interactive input and shell PID continuity across detach/reattach, not every app UI lifecycle. Acceptance targets below remain requirements unless separately recorded as passed.

REA packaged-app observations and source observations are separate. A matching name/version does not establish that the installed app was built from the reference commit. See [investigation](SUPACODE-EVIDENCE.md) and any later retained REA evidence.

## Deliberate differences

The user requested an independent implementation and no telemetry. Supacode code/assets are not adopted. Grove uses the MIT-licensed SwiftTerm terminal renderer rather than Ghostty; renderer-specific configuration is not automatically compatible. Analytics and crash-report uploads are intentionally excluded, even though upstream has preferences for them.

## Completion rule

For each row, attach the implementing file, one behavior-focused check or clearly labeled manual scenario, observed result, and unresolved platform/auth/provider limits. A feature is not complete because a button, setting, dependency or source stub exists. Background persistence requires process continuity evidence; SSH requires an actual remote fixture; forge writes require an actual server-side result; updates require signing/feed verification. Preserve these distinctions in release notes.
