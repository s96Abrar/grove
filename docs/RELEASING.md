# Building and releasing Grove

This is the release *process*. For what ships next and the step-by-step checklist, see the [release plan](RELEASE-PLAN.md).

## Accepted distribution policy

**User decision: skip Apple signing and notarization.** Grove intentionally distributes ad-hoc-signed, non-notarized builds. Apple Developer ID certificates, Apple credentials, notary submission, stapling and Apple trust assessment are outside the current release scope. Their absence is accepted policy, not a bug, incomplete task, missing prerequisite or reason to repeatedly flag production readiness. See [AGENTS.md](../AGENTS.md) for agent guidance. Revisit this policy only on an explicit user request.

Ad-hoc signing remains for executable/bundle integrity and hardened runtime; it does not require an Apple account. Artifact descriptions and manifests must remain accurate. macOS can still apply its normal trust prompts or restrictions to downloaded builds. That known distribution property is accepted; it does not justify disabling system protection or suppressing actual launch/signature failures.

## Release policy

Releases are **tagged only**, with no scheduled release or automatic version bump. Normal CI checks run on main pushes, pull requests or an explicit manual run. The release workflow runs only on a pushed `vMAJOR.MINOR.PATCH` tag and rejects a version mismatch or dirty checkout.

The repository is hosted on GitHub (`s96Abrar/grove`). CI runs there on pushes to `main` and on pull requests, and the release workflow publishes GitHub Releases from version tags. No Apple secrets or signing environment setup are required.

`release.json` is the single version/build/bundle-identifier/minimum-OS source. Increase the build number when preparing a release. Grove's own source is MIT-licensed; dependency notices are embedded. Runtime telemetry and activation remain excluded.

## Local builds and checks

```sh
make build
make check
make lint
make package
```

Persistent terminals require a separately installed tmux executable (`brew install tmux`), tested with 3.8. tmux is not bundled; the package includes Grove’s tmux.conf and validates its presence. CI installs tmux on each test runner. Legacy screen sessions remain reattachable. See [compatibility and migration](TERMINAL-COMPATIBILITY.md).

`make build` creates `dist/Grove.app` for the host architecture with a hardened-runtime ad-hoc signature. The icon master is Resources/AppIcon.png; its editable vector source is scripts/render-icon.swift, regenerated by make icon. Packaging includes all standard macOS icon sizes.

`make check` exercises real temporary Git repositories, workspace backup/corruption recovery, release policy, PTY/screen input and continuity, bundle validation and the actual app termination/relaunch harness. The GUI harness uses a temporary workspace and cleans up its own instances/session. It needs a logged-in graphical macOS session.

`make lint` downloads checksum-pinned Actionlint 1.7.12 into the ignored build folder on first use. It validates workflow structure and expressions without running hosted CI.

`make package` creates a host-architecture local ZIP, SHA256SUMS and build manifest under `dist/releases/<version>-local/`. For both architectures:

```sh
GROVE_ARCHS="arm64 x86_64" python3 scripts/release.py --mode local
```

Local files have a `-local` suffix and a `local-adhoc` manifest. Tagged releases use `tagged-adhoc` and explicitly record `notarized: false`. Both are valid outputs under the accepted policy. Existing release folders are never silently replaced; preserve or intentionally remove only the generated previous output before rebuilding the same version.

## Tagged release gates

The pipeline requires:

- An exact version tag pointing to HEAD and a clean Git checkout.
- Both arm64 and x86_64 slices for tagged releases.
- Correct bundle/version metadata, icon, notices and build provenance.
- A valid ad-hoc integrity signature with hardened runtime.
- Final ZIP extraction/validation, checksums and a truthful release manifest.

Apple credential, notarization and trust-assessment gates are intentionally absent. Scripts perform no Apple submission and import no certificate/private key.

Local tag checks and packaging, after creating the matching tag:

```sh
python3 scripts/release.py --mode tagged --tag v0.3.0 --preflight-only
python3 scripts/release.py --mode tagged --tag v0.3.0
```

## Prepared CI/CD

- `.github/workflows/ci.yml`: native Apple Silicon macOS 26 runner, Xcode 26.6, application checks, workflow lint and local developer artifacts. The Intel runner was removed by user decision (2026-11-26); the x86_64 slice is still compiled and verified for tagged releases but is not executed in CI. CI restores SwiftPM build products (`.build/review-tests`, `.build/release-arm64`) from an Actions cache keyed on the Xcode path and `Package.swift`/`Package.resolved`; the release job builds from a clean checkout without it.
- `.github/workflows/release.yml`: tag push → reusable quality matrix → universal ad-hoc build → bundle/archive validation → GitHub Release containing ZIP, checksums and manifest.

Official actions are pinned to immutable commits. Checkout credential persistence is disabled. Quality jobs have read-only content permission; only publication gets content-write permission. The release job uses the repository's built-in GitHub token, not Apple secrets. The `release` GitHub Environment may be configured with reviewers to control publication.

To publish, push a matching reviewed tag from an up-to-date `main`:

```sh
git tag -a v0.3.0 -m "Grove 0.3.0"
git push origin v0.3.0
```

Published tags/releases should remain immutable; fix a mistake with a new patch release.

## Remaining validation boundaries

Validation results are in [VALIDATION.md](VALIDATION.md). Minimum macOS 14 runtime compatibility and native Intel runtime behavior still require their respective test hosts. The current local host proves Apple Silicon operation; a compiled Intel slice is not an Intel runtime test. Legacy screen terminal-protocol limitations, authenticated agent scenarios, full Supacode parity and automatic updates remain separate work. Apple signing/notarization are excluded scope, not entries in that work list.

### Cross-compilation toolchain note

The build uses SwiftPM's native engine, separate architecture caches and explicit minimum-OS target triples so build-time helpers remain host-native. Swift 6.4 marks that engine deprecated; CI is pinned to Xcode 26.6. Revalidate this path before upgrading toolchains or removing the fallback. No Rosetta installation or sandbox disable is performed.
