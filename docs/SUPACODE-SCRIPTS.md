## What “default scripts” means

Supacode provides predefined **categories and presentation**, rather than universal executable commands. Its kinds are Run, Test, Deploy, Lint, Format and Custom, with a default display name, SF Symbol and tint per kind. A new definition's command is empty. A fresh repository has no named scripts and its setup, archive, delete and open-file commands are empty; global scripts also start empty. See [ScriptKind.swift, lines 6–52](https://github.com/supabitapp/supacode/blob/1ffcc2e93c3f74fe3d52183176542fa8852ad2ba/SupacodeSettingsShared/Models/ScriptKind.swift#L6-L52), [ScriptDefinition.swift, lines 36–50](https://github.com/supabitapp/supacode/blob/1ffcc2e93c3f74fe3d52183176542fa8852ad2ba/SupacodeSettingsShared/Models/ScriptDefinition.swift#L36-L50), [RepositorySettings.swift, lines 44–59](https://github.com/supabitapp/supacode/blob/1ffcc2e93c3f74fe3d52183176542fa8852ad2ba/SupacodeSettingsShared/Models/RepositorySettings.swift#L44-L59) and [GlobalSettings.swift, lines 190–225](https://github.com/supabitapp/supacode/blob/1ffcc2e93c3f74fe3d52183176542fa8852ad2ba/SupacodeSettingsShared/Models/GlobalSettings.swift#L190-L225).

Supacode's own repository supplies a checked-in `supacode.json` with these project commands:

| Entry | Command |
| --- | --- |
| Run | `make run-app` |
| Test | `make test` |
| Lint | `make check` |
| Format | `make format` |
| Setup | `git submodule update --recursive` |

These are settings for developing **Supacode itself**, not commands installed into every project. Evidence: [supacode.json, lines 1–36](https://github.com/supabitapp/supacode/blob/1ffcc2e93c3f74fe3d52183176542fa8852ad2ba/supacode.json#L1-L36). ## Definitions, ownership and configuration

Each named script has a UUID, kind, name, command and optional icon/tint overrides. Predefined kinds resolve their fixed kind presentation; Custom resolves its user presentation. Repository scripts precede globals, and a repository definition shadows a global **by UUID**, not by name or kind. The first Run-kind entry is the primary action. Evidence: [ScriptDefinition.swift, lines 6–98](https://github.com/supabitapp/supacode/blob/1ffcc2e93c3f74fe3d52183176542fa8852ad2ba/SupacodeSettingsShared/Models/ScriptDefinition.swift#L6-L98).

The repository editor offers each predefined kind until that kind exists, plus unlimited Custom entries. Global additions are Custom. See [RepositoryScriptsSettingsView.swift, lines 58–122](https://github.com/supabitapp/supacode/blob/1ffcc2e93c3f74fe3d52183176542fa8852ad2ba/SupacodeSettingsFeature/Views/RepositoryScriptsSettingsView.swift#L58-L122) and [SettingsFeature.swift, lines 901–904](https://github.com/supabitapp/supacode/blob/1ffcc2e93c3f74fe3d52183176542fa8852ad2ba/SupacodeSettingsFeature/Reducer/SettingsFeature.swift#L901-L904).

Local repository settings first read the root's `supacode.json`; absent files fall back to the app's per-repository settings, then defaults. Global configuration and repository fallback live in separate `config.json` and `repos.json` files. Remote repositories use the app fallback instead of reading their remote path on local disk. Legacy `runScript` settings migrate to a Run definition when `scripts` is absent; encoding derives the old field from the first Run entry. Evidence: [RepositorySettingsKey.swift, lines 35–67](https://github.com/supabitapp/supacode/blob/1ffcc2e93c3f74fe3d52183176542fa8852ad2ba/SupacodeSettingsShared/BusinessLogic/RepositorySettingsKey.swift#L35-L67), [SupacodePaths.swift, lines 175–194](https://github.com/supabitapp/supacode/blob/1ffcc2e93c3f74fe3d52183176542fa8852ad2ba/SupacodeSettingsShared/Support/SupacodePaths.swift#L175-L194) and [RepositorySettings.swift, lines 110–117 and 143–156](https://github.com/supabitapp/supacode/blob/1ffcc2e93c3f74fe3d52183176542fa8852ad2ba/SupacodeSettingsShared/Models/RepositorySettings.swift#L110-L156).

## Launch, stop and completion

- The toolbar's primary button runs the primary script; its menu lists repository/global actions, stop actions and configuration links. Empty commands are disabled there. Command-palette requests re-resolve the definition against current settings and route blank commands to configuration. [WorktreeDetailView.swift, lines 1325–1411](https://github.com/supabitapp/supacode/blob/1ffcc2e93c3f74fe3d52183176542fa8852ad2ba/supacode/Features/Repositories/Views/WorktreeDetailView.swift#L1325-L1411), [AppFeature.swift, lines 1210–1255](https://github.com/supabitapp/supacode/blob/1ffcc2e93c3f74fe3d52183176542fa8852ad2ba/supacode/Features/App/Reducer/AppFeature.swift#L1210-L1255).
- Default shortcuts are Command-R to run and Command-period to stop. The global Stop action targets Run-kind scripts, rather than every kind. [AppShortcuts.swift, lines 576–577](https://github.com/supabitapp/supacode/blob/1ffcc2e93c3f74fe3d52183176542fa8852ad2ba/SupacodeSettingsShared/App/AppShortcuts.swift#L576-L577), [BlockingScriptKind.swift, lines 49–56](https://github.com/supabitapp/supacode/blob/1ffcc2e93c3f74fe3d52183176542fa8852ad2ba/supacode/Features/Terminal/Models/BlockingScriptKind.swift#L49-L56).
- A named script gets a dedicated locked, ephemeral terminal tab. Starting an already tracked active script selects its tab; a completed lingering tab is replaced on the next run. These launches explicitly bypass zmx persistence. Closing matching script tabs implements Stop. [WorktreeTerminalManager.swift, lines 1124–1223](https://github.com/supabitapp/supacode/blob/1ffcc2e93c3f74fe3d52183176542fa8852ad2ba/supacode/Features/Terminal/BusinessLogic/WorktreeTerminalManager.swift#L1124-L1223).
- Local script text is written into an owner-only temporary directory (0700; script files 0600) and run using the selected shell with login initialization. A wrapper emits OSC 133 start/completion markers, preserves the exit status and keeps a finished TTY transcript open in a read-only state. This is distinct from injecting a command into a persistent interactive shell. [BlockingScriptRunner.swift, lines 30–119](https://github.com/supabitapp/supacode/blob/1ffcc2e93c3f74fe3d52183176542fa8852ad2ba/supacode/Features/Terminal/BusinessLogic/BlockingScriptRunner.swift#L30-L119).
- Surface environment includes worktree/root paths, repository/worktree/tab/surface identity, CLI/socket context, plus blocking-script markers and script ID/kind/scope. [Worktree.swift, lines 121–128](https://github.com/supabitapp/supacode/blob/1ffcc2e93c3f74fe3d52183176542fa8852ad2ba/supacode/Domain/Worktree.swift#L121-L128), [TerminalSurfaceRecipe.swift, lines 89–125](https://github.com/supabitapp/supacode/blob/1ffcc2e93c3f74fe3d52183176542fa8852ad2ba/supacode/Features/Terminal/Content/TerminalSurfaceRecipe.swift#L89-L125), [BlockingScriptKind.swift, lines 59–74](https://github.com/supabitapp/supacode/blob/1ffcc2e93c3f74fe3d52183176542fa8852ad2ba/supacode/Features/Terminal/Models/BlockingScriptKind.swift#L59-L74).

## Lifecycle hooks

Setup is consumed once for a newly created worktree and supplied as initial terminal input; it is separate from the tracked blocking-script runner. Archive/Delete run before the corresponding state transition. Setup/Archive settings are hidden for plain folders; Delete remains available for folder removal. Open File is another separate hook: repository command, otherwise global command, otherwise the system app, with the selected path in `SUPACODE_FILE_PATH`. See [RepositoryScriptsSettingsView.swift, lines 16–55](https://github.com/supabitapp/supacode/blob/1ffcc2e93c3f74fe3d52183176542fa8852ad2ba/SupacodeSettingsFeature/Views/RepositoryScriptsSettingsView.swift#L16-L55), [GlobalScriptsSettingsView.swift, lines 16–25](https://github.com/supabitapp/supacode/blob/1ffcc2e93c3f74fe3d52183176542fa8852ad2ba/SupacodeSettingsFeature/Views/GlobalScriptsSettingsView.swift#L16-L25) and [WorktreeTerminalManager.swift, lines 1084–1095](https://github.com/supabitapp/supacode/blob/1ffcc2e93c3f74fe3d52183176542fa8852ad2ba/supacode/Features/Terminal/BusinessLogic/WorktreeTerminalManager.swift#L1084-L1095).

Successful Archive/Delete completion advances the operation; cancellation or failure does not silently complete it. Archive's failure handler exposes an error. Evidence: [RepositoriesFeature.swift, lines 958–995](https://github.com/supabitapp/supacode/blob/1ffcc2e93c3f74fe3d52183176542fa8852ad2ba/supacode/Features/Repositories/Reducer/RepositoriesFeature.swift#L958-L995) and [delete completion, lines 1387–1458](https://github.com/supabitapp/supacode/blob/1ffcc2e93c3f74fe3d52183176542fa8852ad2ba/supacode/Features/Repositories/Reducer/RepositoriesFeature.swift#L1387-L1458).

## Independent Grove design guidance

Grove can offer the familiar categories, editable named commands, global/repository scope and explicit terminal execution within its own existing model. Useful starter commands should be **Grove-owned presets** matched to the actual project, reviewed before adding and never silently executed. Supacode's own Make targets should not be installed into unrelated repositories. Preserve existing scripts and metadata when adding defaults; adding again should not duplicate or overwrite customized entries.

Lifecycle hooks, tracked exit status, process stopping, locked transcripts and configuration-file interchange are distinct behaviors. A command editor plus terminal tabs alone must not be described as full Supacode script parity. Grove's user guide and feature-parity document describe the implementation actually delivered.
